# MacKit

macOS 日常维护工具箱 —— 把零碎的维护操作收拢到一个本地网页界面上，点点鼠标就能用。

核心零依赖：后端只用 Node 内置模块，前端是原生 HTML/CSS/JS，不需要 `npm install`，不装任何 npm 第三方包。唯一的例外是**可选的「音乐下载」模块** —— 它按需在 `~/.mackit/py` 下装一个隔离的 Python 环境（`musicdl`，仅限非商业用途）；不装它，其余 7 个模块照常离线可用。

服务只监听 `127.0.0.1`，局域网内其他设备访问不到。

## 能做什么

| 模块 | 用途 |
| --- | --- |
| **总览** | 一键体检：Homebrew / Git / Rime / 代理等环境状态一览；旁边还有 **MacKit 自身更新** 按钮（有新版本时高亮） |
| **Homebrew 管家** | 列出可升级的软件包并逐项选择「代理 / 直连」升级；搜索并安装 Formula（命令行工具 / 库）与 Cask 应用；卸载 formula / cask / tap；本机没装 Homebrew 时可一键安装 |
| **音乐下载** | 输入关键词跨 57 个音源搜索、勾选后批量下载到本地，也可粘贴歌单 / 专辑链接批量解析。Python 依赖**按需**装到 `~/.mackit/py`，不用时一键卸载（见下文「音乐下载」） |
| **系统初始化** | 把代理别名写进 shell 配置、设置 Git 全局项、把 GitHub Token 存进 macOS 钥匙串、配置代理端口 |
| **Rime 输入法** | 安装 / 更新 rime-ice 词库，切换皮肤与布局，启用万象语法模型，写入配置 |
| **应用解隔离** | 批量去掉 App 上的 quarantine 属性（解决"打不开 / 已损坏"） |
| **备份中心** | 把上述配置备份到你的 WebDAV 服务器（NAS），换机器时一键恢复 |

## 环境要求

- **macOS**（Apple Silicon / Intel 都可以）
- **Node.js 20 或更高** —— 终端里执行 `node -v` 看一眼。没有的话：
  - 已装 Homebrew：`brew install node`
  - 没装：到 <https://nodejs.org> 下载安装包

除「音乐下载」模块外，不需要联网，也不需要安装任何依赖；音乐模块首次使用时需联网装一次 Python 依赖（见下文）。

## 快速开始

### 1. 拿到代码

```bash
git clone https://github.com/Giaosm/MacKit.git
```

或者点页面右上角 **Code → Download ZIP** 再解压（这种方式要多做一步「修复权限」，见下文）。

> **别把它放在「下载 / 桌面 / 文稿 / iCloud 云盘」里。** 这几个是 macOS 的受保护目录，从启动台启动的 MacKit 会被系统拦在外面，症状是点了图标没反应（安装脚本检测到会警告你）。放在 `~` 下面最省事 —— 先 `cd ~` 再克隆。

### 2. 双击安装（只需一次）

双击仓库根目录的 **`install.command`**。

会弹出一个终端窗口，它做四件事：

- 补上可执行位、清掉 macOS 的隔离标记；
- 在 `/Applications/` 生成一个带图标的 **MacKit.app**（和别的软件放在一起，**不需要管理员密码**）；
- 记下程序所在目录，以后从这里启动；
- 清掉早期版本可能遗留在 `~/Applications` 的旧副本。

看到「✅ 安装完成」后按回车，窗口自动关闭。

### 3. 打开

**启动台**，或 **Spotlight（⌘ + 空格）搜索「MacKit」**，点一下就开。也可以把 `/Applications/MacKit.app` 直接拖进 Dock。

（启动台偶尔要过几秒才收录新装的 app，等不及就用 Spotlight 搜。）

浏览器会自动打开界面，左侧边栏切换各个模块。所有涉及系统改动的操作，界面都会先弹确认框，并显示即将执行的命令。

> 只想临时用一次、不想安装？直接进 `app` 文件夹双击 `MacKit.command` 也一样，只是每次都得自己找目录。
>
> 移动或改名了 MacKit 目录之后，在新位置重新双击一次 `install.command` 即可，数据不受影响。

## 如果双击没反应 / 提示"无法验证开发者"

这两种情况都只影响 **Download ZIP** 下载的代码（`git clone` 不会有）：macOS 会给文件打上隔离标记，并且**丢掉 `.command` 的可执行位**，双击就会没反应或提示无法打开。

在终端里执行一次：

```bash
chmod +x install.command app/MacKit.command
```

然后**右键点 `install.command` → 选「打开」**，在弹窗里再点一次「打开」。之后就能正常双击了。

## 怎么关闭

界面**右上角**有一个「关闭服务」按钮。点它，后台服务就停了，页面会提示"服务已关闭"，这时可以放心关掉标签页。

**直接关掉浏览器标签页也可以** —— 后台服务会继续运行。这样做的好处是：正在进行的升级、下载任务不会被中途打断。想再回到界面，从启动台再点一下 MacKit 即可，之前的数据和进度都还在。

如果要彻底停掉后台服务，重新打开界面点一下「关闭服务」。

## 更新 MacKit

总览页右上角、**「⟳ 重新体检」旁边**有一个 MacKit 自身的更新按钮（MacKit 本体是 git 检出，所以「有没有新版本」= 本地 HEAD 与 `origin/main` 比）：

| 状态 | 按钮 |
| --- | --- |
| 远端有新提交 | **`更新 MacKit（N 个新提交）`** —— 高亮可点，鼠标悬停能看到最新提交的标题 |
| 已是最新 | **`已是最新`** —— 置灰 |
| 不是 git 检出（ZIP 下载的） | **`无法自动更新`** —— 置灰，到 GitHub 重新下载即可 |
| 查不到（离线 / 代理不通） | **`检查更新`** —— 可点，点它会真去 fetch 一次 |

点下去先弹确认框，然后执行的就是：

```bash
git fetch --prune origin                # 看远端有没有新提交
git diff --name-only HEAD..origin/main  # 预检：这次更新会改哪些文件
git pull --ff-only                      # 只做快进合并
```

安全约定：

- **只用 `--ff-only`**：不产生 merge commit；历史一旦分叉，git 会直接拒绝，而不是把两边合起来。
- **绝不动你的本地改动**：不 stash、不覆盖、不丢弃。如果未提交的改动正好撞上本次要改的文件，按钮会在动手**之前**停下来，并告诉你冲突的是哪几个文件。
- 检查**带 10 分钟缓存**，所以打开总览不会每次都联网；点按钮或更新完会强制重新检查一次。

⚠️ **更新完要重启才生效**：前端文件是每次请求现读的，刷新页面就够了；但后端代码（`app/lib/`、`server.js`）在服务启动时加载，必须重启服务。

界面会自己识别这种情况：服务把「启动时加载的后端代码指纹」和磁盘上的现状做比对，发现不一致就在页面顶部挂一条**「后端代码已更新，当前服务仍在运行旧版本」**的横幅（前端文件改了而页面没刷新时，则会挂一条「前端文件已更新，请刷新页面」），点里面的「立即重启」即可 —— 后端会先拉起一个脱离父进程的新服务（沿用同一端口），再退出旧进程，页面自动刷新，不需要你去 Finder / Dock 里操作。也可以按老办法：右上角「关闭服务」，再重新双击 `app/MacKit.command`。

另外，Homebrew 上游的分发偶尔会滞后（同一时刻 `cask.json` 里已经是新版本，而 `brew outdated` 读到的元数据还是旧一代），表现为「点了更新却显示 0 项可更新」。这种情况不是本机问题：「一键更新本体并刷新索引」的最后一步会**核对**这两份数据，发现不一致就在任务日志里写明是哪一项、索引里是多少、brew 元数据里是多少，隔几分钟再点一次通常就好了。

## 数据放在哪

运行数据都在 `~/.mackit/` 下：

| 路径 | 内容 |
| --- | --- |
| `config.json` | 你的设置（权限 600） |
| `runtime.json` | 当前服务的端口与进程号 |
| `logs/` | 各次任务的执行日志（保留最近 50 个任务 / 30 天；权限 600，与配置同口径） |
| `history/` | 任务历史（保留最近 10 次） |
| `cache/` | Homebrew 环境快照（30 秒）、Formula / Cask 搜索索引（24 小时）、MacKit 自更新检查（10 分钟）、音乐搜索快照 |
| `py/` | **可选**：音乐模块的隔离 Python 环境（`venv/`）与 pip 缓存（`cache/`）。没用过音乐模块时不存在；随「卸载音频环境」整体删除 |
| `server.out` | 服务启动日志 |
| `app-launch.log` | 从启动台 / Dock 每次启动的记录（退出码 + 输出），启动出问题时看它 |
| `webdav.json` | WebDAV 备份凭据（明文，权限 600） |

**安装时写进去的东西只有两处**：`/Applications/MacKit.app`（启动用的外壳）与 `~/.mackit/`（运行数据）。

## 音乐下载（可选模块）

侧边栏的 **音乐下载** 模块：输入关键词 → 跨 **57 个音源**（QQ音乐 / 网易云 / 酷狗 / YouTube Music / 喜马拉雅…）搜索 → 勾选后批量下载到本地；也可以粘贴歌单 / 专辑 / 频道链接批量解析，再按同样的方式勾选下载。

它是**唯一**打破「零依赖」承诺的模块，因此被刻意隔离：

- **依赖装在哪**：独立虚拟环境 `~/.mackit/py/venv`（pip 缓存在 `~/.mackit/py/cache`）。**全程不使用 sudo、不写系统目录、不碰系统自带的 python3**；下载的音乐文件默认落在 `~/Music/MacKit`，可随时改目录，并支持**一键在 Finder 打开**（目录不存在会自动创建）。
- **首次使用**：页面会显示「未就绪」，点「安装音频环境」→ 弹确认框列出即将执行的命令、体积与许可 → 确认后自动执行：
  ```bash
  python3.12 -m venv ~/.mackit/py/venv
  ~/.mackit/py/venv/bin/pip install -U pip musicdl
  ~/.mackit/py/venv/bin/python -c "import musicdl"
  ```
  需要 Python 3.12+。若本机没有，页面会引导你到「Homebrew 管家」安装 `python@3.12`（`brew install python@3.12`），**不代装、不提权**。
- **体积 / 耗时**：约 **300–500 MB**（另需 ≥ 1.5 GB 可用磁盘），数分钟，**需要联网**（从 PyPI 下载）。
- **可逆**：随时可在本页点「卸载音频环境」删除 `~/.mackit/py`（**已下载的音乐文件不会被删除**），之后也可再次安装。
- **不破坏其余模块**：未安装时音乐模块只显示引导页；后端对 Python 的探测是**懒加载**的，7 个既有模块的启动与运行完全不依赖它。
- **并发**：音乐下载走独立的并行通道，**不会阻塞** Homebrew 升级等其它任务（两者可同时进行）。

## 卸载

双击仓库根目录的 **`uninstall.command`**，它会：

- 停掉正在运行的后台服务（优雅退出，正在跑的任务会被告知终止）；
- 删掉 `/Applications/MacKit.app`（早期版本装过的 `~/Applications/MacKit.app` 也会一并查找）；
- 问你要不要连 `~/.mackit/` 一起删（**默认保留**，里面有配置和 WebDAV 凭据）。

**程序目录它不会动** —— 那是你自己克隆下来的文件夹，确认不需要了再自己删。

下面这些是功能写入的、不是安装产物，脚本不会碰，按需自行清理：

- shell 配置里的别名与 `brew shellenv`（`~/.zshrc` / `~/.zprofile` / `~/.bash_profile`）
- macOS 钥匙串里的 GitHub 凭据（钥匙串访问 → 搜 `github.com`）
- `~/.brewgo_config`（代理端口 / 镜像源，与旧脚本共用）

## 说明

- 端口默认 `18080`。若被占用会自动往后顺延，实际端口显示在启动日志里。
- 部分操作需要授权：安装 Homebrew 会要求管理员密码（通过系统弹窗输入，密码不落盘、不写日志）；修改 `~/Library/Rime` 下的配置、去除系统 App 的隔离属性也可能需要管理员权限。
- 涉及删除或覆盖的操作（卸载软件包、覆盖别名、覆盖配置等）一律有二次确认。
- 应用图标由 `tools/make-icon.mjs` 用代码画出来（零依赖，不需要任何设计工具），想换配色或形状改几个常量重跑即可，用法见该文件头部注释。
- 从启动台 / Dock 再点一次 MacKit 时，如果界面已经在浏览器里开着，它会直接把你带到那个标签页，**不会再新开一个**。这件事要用一次浏览器的自动化权限：首次打开时系统会问「MacKit 想要控制 Google Chrome」，点「允许」即可；点「不允许」也照样能用，只是每次会新开标签页。
